## Why plan 001 was shipped

The brief asked for the highest-leverage plan that is a real feature grounded in
repo evidence or a substantial correctness/safety fix, verifiable by the repo's
own tests. Plan 001 is both:

- **Safety**: `place_order` is the only tool that creates brokerage exposure,
  and its caller is an LLM agent. A definite broker rejection and an ambiguous
  transport failure (the order may exist) both rendered as `Error: Internal
  server error`, and no client order ID was sent. So the order could not be
  reconciled, and a retry could create a duplicate order.
- **Direction**: ROADMAP.md's "paper decision journal" acceptance criterion is
  "an ambiguous response is never replayed as another order". ARCHITECTURE.md
  and README list submission idempotency as missing. The installed Alpaca SDK
  documents client order IDs as the reconciliation mechanism.
- **Verifiable**: the installed SDK's in-memory transport (`mockFetch`), the
  MCP test client and the paper-only stdio e2e fixture cover the behaviour
  end to end with no network or credentials.

Plan 002 (stdout corruption) is also P1 but is a small, narrower fix. It is a
good next candidate.

## Direction suggestions

These are options for the maintainer to weigh, not ranked problems.

- **Explainable research snapshot (ROADMAP "Now")**: `ScanResultSchema`
  (`packages/screener/src/contracts.ts`) drops quote provenance (`source`,
  `kind`, `timestamp`, `retrievedAt`), and scan predicates return bare booleans,
  so nothing records why a symbol matched or was excluded. A first spike would
  add provenance and per-symbol match/exclusion reasons to `ScreenerService.scan`
  and expose it as an MCP `scan` tool, then decide on storage. Vercel has no
  durable filesystem, so storage is the open question. Effort: L overall (M for
  the provenance and reasons slice).
- **Paper decision journal (ROADMAP "Next")**: plan 001 provides the
  prerequisite of reconcilable, non-replayable submission. The journal can key
  each thesis to a `clientOrderId` and later reconcile it via
  `get_order_by_client_id`. Effort: M–L.
- **Expose already-built research reads**: `unified.getNews`, `getSentiment`,
  `getMacro`, `getRecommendations`, `getEarningsCalendar`
  (`packages/core/src/providers/index.ts`) have no callers. Several return `[]`
  on failure, which conflicts with the "missing ≠ empty" contract, so give each
  an unavailable-vs-empty result first. Effort: S–M per family.

## Findings considered and rejected

- **FRED `getLatest` returns null when the newest observation is "."**:
  by design. `docs/data-contracts.md` says "the latest value remains
  unavailable when the most recent observation is missing; it is not replaced
  by an older one".
- **"`export const client` in alpaca.ts is unused, delete it"**: wrong
  evidence. `packages/core/test/alpaca.transport.test.ts` spies on
  `client.trading` and `client.marketData`. The eager construction at import is
  a minor issue, and the untangle decision log keeps public exports.
- **Retire the pinned "pre-fix regression proof" CI step**: deliberate, per
  `docs/reliability-audit.md` ("The baseline check is pinned deliberately").
  It is the maintainer's call, not a defect.
- **Delete unused cache/rate-limiter helpers and unused schemas**: the untangle
  decision log records "keep public infrastructure/config exports even if
  internally unused".
- **Parallelize REST scans without bounds**: the decision log records that
  sequential scans protect upstream request pressure. Finding 7 proposes
  caching or bounded concurrency instead.
- **Symbol/series IDs interpolated unencoded into provider URLs**: hosts are
  constants and REST validates symbols, so exploitability is low. This is folded
  into the symbol-schema debt item rather than planned as security.
- **Zod 4 deprecated `z.ZodIssueCode` / `.format()`**: deprecation only, no
  removal date; it does not belong in this backlog.
